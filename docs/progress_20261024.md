# 2026-10-24 · 适配 SukiSU v4.2.1-r1 / FinaSU v1.0.7（uapi 6）

## 结论

两家新管理器都是 **KernelSU 分支 + `KERNEL_SU_UAPI_VERSION = 6`**，跟现有的 uapi5 ko 不兼容
（管理器会显示「需要更新内核」或 ioctl 全拒）。已各编一份 ko，真机验收**未完成**（设备当时离线）。

| FinaSU | `me.yuki.fina` | v1.0.7 (32997) | `kernelsu_finasu.ko` | `e8b82bb04c5c5b61dc35524042cae80a` | 6,988,688 |

## 关键坑：fork 的 setup.sh 不能直接用

`FinaSU` 的 `kernel/setup.sh` 里 `git clone` 写死成 `https://github.com/tiann/KernelSU`
——照它跑会拿**上游源码**编出一份冒充 FinaSU 的 ko（uapi 可能都对，但模块内部对不上）。

workflow 因此加了 `ksu_tarball` 输入：填了就走「下载 tarball → 解包到 `KernelSU/` →
自己 `ln -sfn ../KernelSU/kernel drivers/kernelsu` + Makefile/Kconfig 三件套」，完全绕开 setup.sh。
`ko_alias` 决定产物名（`sukisu`/`finasu`）。

## ksud 也得对上 uapi

SukiSU 的 APK 里**没有** `lib/arm64-v8a/libksud.so`，它把 ksud 改名成 `libdhxddxovny.so`
（5.9 MB，ELF，里面能 grep 到 `ksud::su` / `4.2.1-r1 (uapi: 6)`）。FinaSU 是标准名。

`ksu_loader.sh` 的 `_extract_mgr_ksud` 已改成两级：

1. 先找 `libksud.so`
2. 没有就从 `lib/arm64-v8a/*.so` 里挑「体积最大（>2 MB）+ ELF magic 正确」的那个

## 其他改动

- `ksu_loader.sh`：`_detect_mgr_pkg`、加冕顺序、`_pick_custom_ko` 都加了两个新包名与 ko 映射；
  ko 候选回退链变成 `首选 → custom → suksisu → finasu → kernelsu.ko`
- `m6-shell`：管理器选项加 SukiSU / FinaSU（共 6 项），`DeviceCheck.manager()` 同步
- 新增 `tools/rebuild_manifest.py`：重算 `MANIFEST.md5` / `bundled_ko.md5` 并 `--sync` 进 assets
- APK 升到 **1.5 (vc5)** —— 载荷变了必须动 vc，否则 `PAYLOAD_STAMP` 可能仍相等 ⇒ 跳过推送
